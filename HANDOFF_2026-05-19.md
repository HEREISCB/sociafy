## TL;DR — what changed

Before this session the app had a real security hole: the TikTok webhook
inserted activity rows even when the HMAC signature was invalid, OAuth
tokens were stored as plaintext in Postgres, `GET /api/accounts` returned
those tokens to the browser, and the `next` OAuth redirect param accepted
arbitrary external URLs. Those are all fixed now. On top of that there's
rate limiting, input validation, error-detail leak fixes, CSRF Origin
checks, token revocation on disconnect, and security response headers.

## What I fixed, by severity

### CRITICAL
- **TikTok webhook accepted unsigned events**. `verifySignature()` ran but the
  body was still parsed and an `activity_log` row was written whenever a
  matching `user_openid` was found. An attacker forging the openId+client_key
  could inject activity into any user's feed. **Fix**: return 401
  `invalid_signature` when the secret is configured and the HMAC doesn't match.
  Also added a 300-second replay tolerance window on `tt-timestamp`.
- **`GET /api/accounts` leaked access/refresh tokens to the browser**.
  The full row was returned including `accessToken` and `refreshToken`. Now an
  explicit `PUBLIC_COLUMNS` projection — tokens never leave the server.

### HIGH
- **Open redirect via OAuth `next` param**. The start route accepted any
  string as `next`, signed it into state, and the callback redirected there.
  Crafted `…/start?next=//evil.com/foo` would round-trip and 302 the user to
  evil.com after OAuth. **Fix**: `lib/safe-next.ts` validates the value at
  both sign and verify time — must be a single-leading-slash path with no
  protocol, host, control chars, or scheme prefix.
- **Plaintext OAuth tokens at rest**. The UI literally claimed "Tokens are
  encrypted at rest" but the columns were `text` with no encryption. **Fix**:
  AES-256-GCM via `lib/crypto/tokens.ts`, ciphertext prefixed `v1:` for
  versioning. Lazy migration — legacy plaintext rows stay readable, and
  `ensureFreshToken` re-encrypts on the next touch so the migration completes
  organically without a backfill script. Key derived from `TOKEN_ENC_KEY`
  (falls back to `INTERNAL_API_SECRET`).
- **`CRON_SECRET` and `INTERNAL_API_SECRET` had dev fallbacks accepted in
  prod**. Misconfigured prod env would silently use `dev-cron-secret-change-me`.
  **Fix**: `checkCronAuth` refuses if secret unset or <16 chars (and uses
  `timingSafeEqual`); `lib/oauth/state.ts` hard-fails at module load if
  `INTERNAL_API_SECRET` is missing or <32 chars under `NODE_ENV=production`.
- **`X-Forwarded-Host` trusted unconditionally**. Host-header poisoning could
  steer OAuth `redirect_uri` to an attacker-controlled hostname. **Fix**:
  `getOrigin` in prod only honors the header if it matches
  `NEXT_PUBLIC_APP_URL` or appears in `TRUSTED_FORWARDED_HOSTS`.
- **No rate limiting** on publish, agent/run, OAuth start, webhooks, or
  compose/variants. The agent and compose paths call Anthropic — they cost
  money per request. **Fix**: `lib/rate-limit.ts` in-process token bucket;
  limits sized per endpoint. Returns 429 + `Retry-After`. Swap the backing
  `Map` for Redis/KV when you scale past one instance.

### MEDIUM
- **Information leakage in 500 responses**. `withUser` returned the raw
  `Error.message` in a `detail` field, leaking DB schema / driver internals.
  **Fix**: in prod, drop `detail` and log server-side only.
- **CSRF on state-changing routes**. Clerk's SameSite=Lax cookie blocks
  cross-site form POST but not all edge cases. **Fix**: `withUser(handler, req)`
  now checks `Origin`/`Referer` matches `getOrigin(req)` on non-GET requests
  and returns 403 `forbidden_origin` otherwise.
- **Webhook idempotency**. Both TikTok and Meta retry on non-2xx and on
  timeouts. Without dedup, an activity row was created per retry. **Fix**:
  hash the raw body as `eventId`, skip insert if a matching event id exists
  in the user's last 50 webhook entries.
- **Unbounded JSON bodies**. Every POST/PATCH accepted any shape and any
  size — Drizzle parameterizes so no injection, but Postgres will happily
  store multi-MB strings. **Fix**: `lib/validation.ts` defines zod schemas
  with length caps for every JSON endpoint. Body parse errors return 400
  with `error: invalid_body`; in prod the per-field issue list is hidden to
  avoid field enumeration.
- **Past `scheduledAt` accepted**. Cron picked them up immediately, which
  almost never matches user intent and was confusing if a typo created the
  date. **Fix**: reject anything earlier than 60s ago at POST + PATCH.
- **Facebook `access_token` in query string** logged by FB edge / CDN /
  proxies. **Fix**: pass via `Authorization: Bearer` header instead. Also
  stopped relaying raw Graph error bodies to clients.
- **Raw Graph error bodies returned to client**. Internal error codes/
  subcodes useful for enumeration. **Fix**: log server-side, return generic
  `graph_page_failed` to client.

### LOW / hygiene
- **`lib/oauth/state.ts`** used `!==` comparison on signatures —
  micro-side-channel risk. Switched to `crypto.timingSafeEqual` with a
  length check.
- **`lib/platforms/x.ts`** used `require('crypto')` inside a function.
  Replaced with a top-level ES import.
- **`app/api/cron/publish`** could pass `undefined` to `eq(draftId, did)`
  on stale rows. Now `.filter(Boolean)` defensively.

## New features (small, defensible)

- **`/api/health`** — uptime monitor target. Cheap `SELECT 1` DB ping and
  config-presence check; returns `503` if anything is off.
- **Token revocation on disconnect** — `DELETE /api/accounts/:id` now
  fires-and-forgets a revoke call to each platform before deleting the row.
  See `lib/platforms/revoke.ts`. Failures are logged but don't block
  disconnect.
- **Production security headers** — CSP, X-Frame-Options SAMEORIGIN, HSTS
  with preload, Referrer-Policy strict-origin-when-cross-origin,
  Permissions-Policy disabling camera/mic/geo/cohort. Dev keeps them off
  so HMR works. CSP allows `'unsafe-inline'` and `'unsafe-eval'` on script
  because Next.js + Clerk inject inline scripts that would otherwise break;
  tighten with nonces over time.

## Open redirect — a small caveat

The `safeNextPath` allowlist is path-only by design. If you ever want to
support an `?next=https://app.sociafy.com/some/page` flow (e.g. multi-app
SSO), add an explicit external-host allowlist there. Don't extend the
existing function — write a new one with its own rules.
